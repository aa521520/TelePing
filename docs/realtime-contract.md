# Realtime TelePing contract

Approved: Cloudflare Free receives Telegram commands immediately; GitHub Actions only runs batch browser checks. All command actions are restricted to the configured private group current creator/administrators. Buttons open a per-user input/confirmation interaction; clicking the first function button NEVER executes that function. Manual slash commands remain supported. Do not promise input-box draft insertion. Keep default 30-minute periodic checks and each-round summaries; no 17CE calls.

## Authority and privacy

One Cloudflare SQLite Durable Object is the only authoritative control/history store. GitHub never writes whole state back. Store authenticated AES-256-GCM encrypted state, inbox/outbox and round data; no plaintext domain keys, credentials, raw API exceptions, message bodies or IDs in public code/logs. Keep persisted values below 2MB and fail safely on overflow. Preserve strict HTTPS and existing browser secret isolation. Use existing STATE_ENCRYPTION_KEY; never regenerate it. Cross-language envelopes are exactly Python crypto.py v1 with nonce/ciphertext base64url and AAD `teleping:v1:<purpose>`.

Worker bindings: STATE (DO namespace). Secrets: TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, BASIC_DOMAINS (initial seed only), STATE_ENCRYPTION_KEY, WEBHOOK_SECRET, RUNNER_API_TOKEN, GITHUB_DISPATCH_TOKEN. Public vars: GITHUB_REPOSITORY, WORKFLOW_FILE=monitor.yml, WORKFLOW_REF=main. No real values in source. Random WEBHOOK_SECRET and RUNNER_API_TOKEN are independent. Service API uses the latter as Bearer token over HTTPS, never URL params; webhook uses X-Telegram-Bot-Api-Secret-Token. Accept only fixed routes/repo/workflow/ref and bounded JSON. /health reveals no private data.

## Service API (POST except health)

Responses/errors must not echo input. Auth failure 401; state/lease mismatch 409; unknown route404. Runner run IDs use GitHub Actions run ID and attempt in the exact format `^[1-9][0-9]{0,29}-[1-9][0-9]{0,9}$`. Idempotent claim and commit. All calls use Content-Type application/json.

- GET /health -> {ok:true, service:"teleping-realtime"}.
- POST /telegram: Telegram secret header, durable update-id dedup and encrypted inbox before successful acknowledgement. Process message/callback/ForceReply; pending processing can be retried by alarm. Preserve pending updates at webhook cutover. Only accept group migrations related to the current bound group through genuine Telegram migration fields/API parameters and reverify new group. Do not rebind by group title/admin coincidence.
- POST /api/setup: Runner Bearer; remove default and configured-chat built-in slash command menus (deleteMyCommands), then send a Chinese function panel with inline callback buttons. It must not set webhook until deployment is explicitly finalized by operator. Return {ok:true}. Runtime data persists encrypted. Repeat setup must not erase targets/history.
- POST /api/claim body {run_id:string, force?:boolean}. force is used for explicit manual acceptance, not scheduled ticks. Claim pending requests or periodic-due work, only one active lease. Return {should_check:false} if idle/busy; otherwise {should_check:true,payload:string}, where payload is an encrypted plan with purpose `plan:<run_id>`.
- Plan plaintext: {run_id,round_id,lease_token,started:number,deadline:number,expected_targets:string[],batches:string[][],expiry_cache:object}. Match existing process_batch fields. Split50, <=6 jobs concurrently in workflow, 5 pages per worker. Deadline=actual claim+25min, lease35min. Record target/request generation and consumed request IDs in DO. /checkone targets need not be monitored. Unfinished targets resume without starvation, and /delete cancels pending temporary targets. A repeat claim for the active lease returns its original plan. A completed run returns `should_check:false`; a fenced old claim returns 409. The service persists a numeric (run ID, attempt) high-water mark plus at most 64 compact completed receipts, rather than retaining full plans indefinitely.
- POST /api/context body {run_id,lease_token} -> {payload:string}, encrypted with purpose `context:<run_id>`. Plaintext {run_id,lease_token,revision:number,started:number,expected_targets:string[],state:object}. expected_targets is only still-valid snapshot generations, including valid temporary requests; deletion+readd must not accept old results. state is projection {targets:string[],site_states:object,pending_targets:[],last_summary:object}; site_states includes only expected targets. Preserve current control changes independently.
- POST /api/commit body {run_id,payload:string}; payload purpose `commit:<run_id>`, plaintext {run_id,lease_token,revision,site_states:object,expiry_cache_updates:object,summary:object,messages:string[],pending_targets:string[]}. Apply only whitelisted history/cache/summary and pending-for-this-round fields; NEVER accept targets/interval/control requests/whole outbox. Verify active lease+epoch, revision, current target generations. On revision mismatch return409 with {code:"revision_conflict"}; Python retries context/recompute up to3 times. On success atomically persist receipt, merge missing work, queue private report chunks and return {ok:true}. Repeated accepted commit with a retained completed receipt returns {ok:true,duplicate:true} without duplicate enqueue; older fenced runs cannot be reopened. Late old leases cannot overwrite current data.

## Realtime control and messages

Refresh getChatAdministrators for EVERY command/callback/final reply. Only real human creator/administrator; reject other chats, private chats, anonymous sender_chat and bots. API failure is deny-by-default and retriable, never stale permissions. Wrong @bot mentions ignored. Dedup recent update IDs independently, not just highest-number, because webhook order can vary. Sessions are bound to chat+user+prompt/nonce and expire10min. A different user cannot continue a session.

Panel: 添加域名、批量添加、查看清单、删除域名、检测全部、检测单个、检测频率、状态、帮助. Add/addmany/delete/checkone buttons send a ForceReply prompt; only the same authorized user's matching reply performs the action. List/check/status/help buttons send confirmation with random nonce, only confirm performs the action. Interval shows allowed values30/60/120/360/720/1440 as second-step buttons. Cancel/expired controls do nothing. Do not use text ReplyKeyboard buttons (they auto-send). Support /menu and existing manual /add /addmany /list /delete /check /checkone /settings /interval /status /help /start. Core target normalization must reject credentials, fragments, whitespace, unsupported schemes, private/loopback literal destinations. JS normalization should match common Python target behavior, including bare domain -> http://host/ and explicit HTTPS retained.

On check intent: durable queue + immediate acknowledgement, then dispatch fixed GitHub workflow (mode=run) via fine-grained PAT with only this repo Actions:write. A current round coalesces later requests into next work, never loses them. Periodic Cloudflare alarm dispatches at configured interval; fixed GH cron is backup. Do not claim Actions finishes instantly. Retry dispatch transient errors with bounded exponential delays; ambiguous successful dispatch may create idle duplicate workflows but cannot duplicate claimed rounds.

Cloudflare is the ONLY Telegram sender in realtime mode. Persist individual UTF16<=3500 chunks, >=3.2s group spacing across calls, retry429 per retry_after using DO alarms, no busy-wait or long-running object. Remove a chunk only after successful delivery; network ambiguity can still duplicate it. Use alarms to retry inbox, dispatch, leases and outbox; avoid scheduling past-due periodic work in a tight loop while a round is active. Keep new command acknowledgements responsive when reports have multiple chunks.

## Python adapter

Add teleping/remote.py. RemoteService(base_url,api_token,key,client=None) uses httpx, HTTPS-only origin, fixed paths, sanitized errors. claim(run_id,force=False)->dict|None decrypts plan; context(plan)->dict decrypts context; commit(plan,context,projection,cache_updates,messages)->None sends encrypted delta. Finish can retry only explicit revision_conflict (max3), recomputing existing reports.complete_round on fresh context and only current valid results. No Telegram calls or GitHub state writes in remote mode. Existing legacy code is retained for rollback but realtime env selects remote branch before _services().

Modify CLI: REALTIME_API_URL set selects remote control/finish. Control uses RUNNER_API_TOKEN+STATE_ENCRYPTION_KEY, writes existing encrypted plan.enc and public matrix indexes. Explicit workflow_dispatch run passes --force; schedule does not. Worker unchanged. Finish must load encrypted plan.enc (workflow notify downloads it), collect encrypted worker files, obtain current context, filter results/cache to expected targets, run existing complete_round, commit delta. No direct notifications. Public output counts only.

Tests: duplicate/unauthorized/anonymous/wrong-group messages; role demotion across input steps; first button has no side effect; per-user sessions; 300 imports; invalid batch atomic; queued request during round survives commit; delete+readd old result excluded; duplicate claim/commit; expired lease; revision retry; temporary check missing work; encrypted storage tamper not reset; outbox UTF16/429/partial retry; webhook secret and runner authentication; Python cross-language envelope compatibility. Local fake transports only, never call production bot or reveal real targets.
