# TelePing design

Public program, private monitoring targets and credentials. Use standard public Linux Actions runners. No paid runners or 17CE calls. Default 30-minute checks of hundreds of targets; benchmark 300. Real Chromium follows HTTP, JavaScript and delayed redirects. Domain-registration and HTTPS certificate expiration are checked. Every completed round produces a brief Telegram group summary, with changed failures, recoveries and expiration warnings. Unknown results never recover a previously confirmed failure. The cloud location is not a China three-carrier measurement.

All targets and credentials originate in Actions Secrets. BASIC_DOMAINS is a first-initialization seed only; thereafter the encrypted state is the authoritative target list, including bot additions and deletions. Never re-add a deleted seed automatically. AES-256-GCM protects persisted state and batch artifacts. Public logs and job names expose only counts and predefined error codes, never target URLs, raw exceptions, page content, screenshots, request endpoints or bot/user/chat identifiers.

Dedicated Telegram bot uses polling only in scheduled Actions runs. Commands: /add URL, /addmany followed by newline-separated URLs in the same message, /list, /delete URL, /check, /checkone URL, /settings, /interval MINUTES, /status, /help. Chinese command-menu descriptions explain that checks and settings are processed at the next scheduled run, not instantly. Only the configured group current owner and administrators may execute commands; query live Telegram roles for each command and fail closed on lookup errors. Supported intervals: 30, 60, 120, 360, 720, 1440 minutes. Force-check commands override the normal due time, not the physical Actions polling interval. Existing webhook conflicts are reported, never silently deleted.

Batch size 50, at most six worker jobs concurrently, at most five pages per worker. Per-site 45-second budget and 15-second stable final-document observation; failed or unconfirmed targets receive one delayed retry. Explicit unknown/unmeasured categories. Persist pending-target ordering to prevent tail starvation. RDAP/expiry caches refresh daily. Plaintext exists only on ephemeral runners; encrypted artifacts retain one day. Control/final jobs persist offset and delivery outbox atomically in an independent state branch. Network ambiguity may duplicate a message; round IDs identify reports.

Deployment requires saving the authorized bot token only in Secrets, binding the intended group, running manual acceptance and then enabling schedules. Never publish credentials. Administrator permissions follow live Telegram group roles. No real private targets are written to this design or tests.
