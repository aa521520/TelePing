# TelePing Implementation Plan

> **For agentic workers:** Use the approved design and test behavior before implementation.

**Goal:** Batch-monitor hundreds of private targets and expose Chinese Telegram menu commands.

**Architecture:** Python control, isolated browser workers, encrypted state/results, summary delivery. GitHub Actions orchestrates a 30-minute polling tick and a six-worker matrix.

**Tech Stack:** Python 3.12, Playwright Chromium, httpx, cryptography, pytest, GitHub Actions.

**Spec:** ../specs/2026-11-03-teleping-design.md

## Global Constraints
- Never commit private targets, bot tokens, chat IDs, admin IDs or encryption keys.
- Public code and logs contain only generic examples, aggregate counts and predefined errors.
- Unknown or unmeasured targets cannot cause recovery notifications.
- Menus are Chinese and disclose delayed command processing.
- BASIC_DOMAINS seeds once; bot changes persist in encrypted state.

## Review Focus
- Authorization and malformed multi-line commands must not change state.
- Missing batch results and queue deadlines must not report unmeasured sites as healthy.
- State authentication failure must never overwrite existing data.
- Bot deletions must survive subsequent seed loading and reboot.
- Encrypted artifacts and sanitized failures must not expose private canaries.
